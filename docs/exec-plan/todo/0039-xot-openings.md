# Add XOT opening rulesets

> **Execution**: Use `/execute-task` to implement this plan. After implementation is complete, use `/review-task` to prepare and create the PR.

## Outcome

An operator can run a Reversi match with an XOT opening: the game master selects a random official eight-move sequence, applies it, then hands the resulting position to the next AI. The large list is the default for XOT; small is available as an optional selection. Existing standard matches remain compatible. Both lists and their provenance are available without an external service during a match. Record durable XOT knowledge for future LLM work. Addresses: none.

## Selection and integration constraints

Each competition selects one ruleset and keeps it fixed: standard, `standard-xot-large`, or `standard-xot-small`. Competitions using these rulesets must be operable separately and concurrently; changing a ruleset during a match is not required. The XOT large ruleset is the default XOT choice. The pinned platform cannot pass the competition's selected ruleset to an external WASM game master before its metadata handshake. The prerequisite is the separate ai-arena plan `docs/exec-plan/todo/0137-wasm-ruleset-selection.md` ([plan PR](https://github.com/yoskeoka/ai-arena/pull/376)); after its implementation merges, pin a revision containing it and consume its startup contract. Package a single immutable game release advertising the supported rulesets, retain the exact-version/digest uniqueness invariant, and verify the actual operator registration, WASI execution, and replay for each competition. Do not claim support based only on direct runner execution.

Use the runner-provided seed for reproducible unbiased list-row selection, defining the missing-seed behavior with actual WASI runtime support. Persist enough information for replay and resume independent of seed or later list changes. Invalid configuration and data fail explicitly. Player init and public snapshots must agree with the state actually used; automatic moves are not billed as AI decisions. Define whether the replay exposes the eight moves or the resulting opening and ensure its transcript can be verified to the final state, including immediate-loss and pass cases.

### Pinned platform constraint discovered during execution

At the pinned `ai-arena` commit `bd2de02252e0e5925aa19402c1ee569588d05a10`, game bundle admission stores the manifest's static runtime arguments in a descriptor. However, `internal/platform/registry/store.go` rejects a second distinct artifact with the same game ID and exact game version. `GeneralSubmissionService` resolves a registration by game ID and major version, and the registry selects the latest release within that major, before checking supported rulesets. Giving the bundles different minor or patch versions therefore does not allow the operator to select all three concurrently either. Direct `arena-runner` bundle execution is a separate path and does not establish general-lane registration support.

The separate platform plan supplies the competition's selected ruleset to the WASM game master at startup while preserving immutable release identity and existing single-ruleset games. Its implementation must merge before this plan's end-to-end acceptance; this Reversi plan does not implement platform changes itself.
